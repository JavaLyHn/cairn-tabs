# AI 整理:彻底加固(容错解析 + 本地兜底 + 自诊断)

## 背景:第 5 次报告,前 4 次都没根治

历次:①提示词精确化 ②提示词放宽 ③max_tokens 1024→4096 + 健壮提取 ④短 token + 回退 1024。
症状在「没能给出可用建议」与「调用失败」之间来回跳。**前几次的通病是:我始终没拿到模型真实输出,靠推断打补丁。**

这次改变策略:不再赌某一个成因,而是**把整条链路上每个会导致「用户看到失败」的环节全部堵死**,
并让失败**自带诊断信息**,同时保证**任何情况下用户都能拿到可用结果**。

## 代码中可验证的四个缺陷(非猜测)

1. **`stripFences` 会吃掉答案**:`extractJsonObject` 先 `stripFences`,而它只取**第一个** ``` 围栏。
   模型若「先输出思考块、再输出答案块」(GLM/DeepSeek 等推理型模型的常见形态),答案被整段丢弃 → null。**上一版我引入的真 bug。**
2. **提示词自我膨胀**:我加的规则「每个标签都要有归宿:恰好出现在 newGroups/assign/unclear 之一」
   **强制模型列举全部 24 个标签 + 中文理由**,是输出体积失控(1024 截断 / 4096 被拒)的直接推手。
3. **schema 零容忍**:模型只要写成 `[0,1]`(数字)、`["0"]`(裸序号)、`"T1"`(大写)、
   `groups`/`tab_ids`/`title`(别名键)、`[{"id":"t0"}]`(对象数组)中任意一种,校验即全部过滤 → 三数组皆空 → null。
4. **失败即死路**:没有任何兜底,用户只能看到一句「没有可用建议」。

## 修复(四层)

### 1. 提取层 —— `extractJsonObject` 重写

**直接扫描原始文本**(不再先 stripFences —— 那正是吞答案的元凶);平衡花括号(跳过字符串内括号)收集所有顶层 `{...}` 段;
逐段解析,**优先返回含预期键**(newGroups/groups/assign/unclear/evict 及别名)的那段,而非单纯「最后一段」。

### 2. 解析层 —— `parseOrganizeResponse` 全面容错

- **键别名**:`newGroups|new_groups|groups`、`assign|assignments|assigns`、`unclear|unsure|unknown`、
  组名 `name|title|groupName|group`、`tabIds|tab_ids|tabs|ids|members`、`taskId|task_id|task|contextId|id`
  (`pick()` 还做大小写/下划线归一)。
- **id 归一 `normalizeToken()`**:接受数字 `3`、裸序号 `"3"`、大写 `"T3"`、带 `#`/空格、对象 `{id:"t3"}`。
- **unclear 兼容裸 id 数组** `["t1", 2]`(reason 可省)。

### 3. 提示层 —— 砍掉输出膨胀

「每个标签都要有归宿」→ 改为「**输出越短越好:没提到的自动留在未分类**;拿不准的直接省略,unclear 仅在想说明原因时用」。
保留「别整个交白卷」的底线。响应体积再降一大截,进一步远离截断。

### 4. 结果层 —— 永不死路 + 自诊断(`organizeOutcome`)

- AI 方案可用 → 照常用。
- 不可用 → **本地兜底 `localGroupSuggestion()`**:同一可注册域名 ≥2 个标签即成一组(纯本地、不联网),
  返回 `AI_PLAN` 并置 **`fallback: true`**;UI 弹「AI 未给出可用建议,已按同网站本地分组」——**如实告知,不冒充 AI 结果**。
- 本地也无可分 → 才报错,且 `detail` 带**可读原因 + 响应片段**(`aiRawHint`:空响应 / 被截断 / 格式异常 + 前 80 字),
  用户无需进控制台即可转述。
