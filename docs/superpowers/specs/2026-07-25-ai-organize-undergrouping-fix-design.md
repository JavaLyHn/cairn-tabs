# AI 整理:治「该分却不分 / 交白卷」——放宽分组提示词

## 现象(用户报告)

未分类里 6 个标签(扩展程序 / 降雨数据可视化 / DeepSeek / QA Platform·Agent 评测 / 睿库API / 睿库生图工作台),
其中「睿库API + 睿库生图工作台」肉眼可见同属一个产品、明显该分到一起,但点「AI 整理」后弹出
**「AI 没能给出可用的分组建议,已保持原样」**——一个组都没建。

## 根因(systematic-debugging)

链路:`ai.error.parse`(`useAiActions.ts`)只在 SW 端 `parseOrganizeResponse` 返回 `null` 时触发;
`parseOrganizeResponse`(`core/ai/organize.ts:267`)仅在**两种**情况返回 null——JSON 不可解析,
**或 `newGroups / assign / unclear` 三者全空**。对话框对「只有 unclear」是优雅处理的(显示列表 + 禁用应用),
所以硬报错 = 计划真为 null = 模型交出了全空 `{newGroups:[],assign:[],unclear:[]}`。

为什么模型交白卷:

1. **默认模型是 `claude-haiku-4-5`**(弱),对模糊指令容错低。
2. **提示词过度保守**:旧版反复强调
   - 「『同一任务』= 明显服务于同一个具体项目/目标。仅仅**同域名、同类型、或主题笼统相关,都【不算】同一任务,不要硬凑**」
   - 「宁可少归、多留 unclear,也不要把不相关的标签凑一起」

   这套为「防乱凑」加的护栏过头了:连「睿库API + 睿库生图」这种**同产品**的明显一对,
   也因「同产品/同域名不算同一任务」被劝退。弱模型一旦找不到窄义的「同一个具体任务」,
   干脆三个数组全空 → null → 硬报错。**护栏挡住了正当分组。**

## 修复(`core/ai/organize.ts` · `buildOrganizePrompt`)

重新平衡提示词,方向从「严格同一任务」放宽到「人一眼会收进同一个文件夹」:

- 目标改写为「像人一眼扫过那样,把**明显该放在一起**的标签归类」。
- 新增「什么叫明显该放在一起」小节(满足任一即可):**同一个产品/服务/站点**(点名「API 文档 + 控制台 + 生图工作台 应归一起」)、
  同一仓库/工单/功能、同一件正在做的事;并明确「哪怕只有 2 个标签也建组」「别因为不够像正式任务而放弃」。
- 保留「别硬凑」护栏,但降为次要:只挡**八竿子打不着**的(短视频娱乐 vs 支付退款文档),真看不出关系的进 unclear。
- **新增硬规则:每个标签都要有归宿(恰好落在 newGroups/assign/unclear 之一),拿不准的一律进 unclear,绝不整个交白卷** ——
  直接堵死「三数组全空 → null → 硬报错」这条路。
- 正向 few-shot 示例改成本次真实案例:`睿库 API 文档 + 睿库 生图工作台 → newGroups:[{name:"睿库",...}]`,
  同时保留「抖音」进 unclear 的反例。
- 「先并入已有任务」「禁止新建与已有任务重叠的重复组」「简短组名」「严格 JSON」等既有约束不变。

保守/激进两档不变量保留:conservative 含「保守」、aggressive 不含「保守」含「跨组」、两档都不含「尽量」、都含 unclear/拿不准。

## 不做

- 不改 `parseOrganizeResponse` 的 null 契约(全空仍 → null;新提示词已让「全空」几乎不再发生,留作真·无结果的兜底信号)。
- 不动单任务净化提示词 `buildPruneTaskPrompt`(语义不同:只踢出界的,不建组)。
- **暂不**把标签 id 从 nanoid 改成短整数索引(弱模型抄 21 位 id 也是潜在失败源,但本次现象更像保守度问题;
  若放宽后仍复现,再做该结构性改造)。

## 模型这个杠杆

提示词只能缓解,分组质量的天花板由模型定。默认 Haiku 4.5 偏弱;设置里换 **Sonnet** 会明显更稳。已多次向用户说明。

- 新增用例:`system` 含「交白卷」(不得三数组全空)。
